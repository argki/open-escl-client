# プロジェクト設計・開発ルール (open-escl-client)

## 1. アプリケーションの基本方針
- 本リポジトリでは、**Brother iPrint&Scan** に代わるスキャナクライアントアプリケーションを開発する。
- **eSCL (AirScan) プロトコル**をベースとし、Brother 製機器に限定しない汎用的なスキャナクライアントを目指す。
- **macOS** と **Windows** の両 OS で利用できるクロスプラットフォーム構成を前提とする。
- **最優先事項**: **「Brother × macOS」** の組み合わせで確実・快適に動作することを最優先とする。

## 2. 設計・実装時の技術指針
1. **eSCL 標準仕様とベンダー固有仕様の分離**:
   - スキャナ探索（mDNS / Bonjour: `_uscan._tcp`, `_uscans._tcp`）、能力取得（`/eSCL/ScannerCapabilities`）、ステータス確認（`/eSCL/ScannerStatus`）、ジョブ実行（`/eSCL/ScanJobs`）は eSCL 標準仕様に準拠してコアモジュールを実装する。
   - Brother 機器特有の XML レスポンスのクセ、名前空間、パラメータ制約、エラー挙動などは、コアロジックにベタ書きせず、ベンダープロファイルやアダプタ層で吸収できるように設計する。
2. **クロスプラットフォーム対応（macOS 最優先）**:
   - ファイルパス、ネットワーク探索、ファイル保存、OS ネイティブ機能連携などは、まず **macOS** での動作を確実に実装・検証する。
   - 同時に、Windows 環境での動作を阻害する macOS 専用のハードコード（パスの `/` 固定や macOS 専用コマンドへの無条件依存など）をコアロジックに直接持ち込まず、OS 抽象化レイヤーまたはクロスプラットフォーム API を用いる。
3. **要件・タスク駆動の開発**:
   - 機能追加や改修を行う際は、`docs/requirements/` 配下の要件ファイル（1ブランチ＝1要件ファイル）およびその中のタスク（1タスク＝1コミット）に沿って進める。
