# タスク実施・Gitブランチ名＆コミットメッセージ提案スキル (`propose-git-commit`)

指定された要件・タスクの実施にあたり、[`.agents/rules/git-conventions.md`](../../rules/git-conventions.md) に準拠した **Gitブランチ名（1種類のみ）** と、プルリクエストの内容をそのまま記載できるレベルの **Gitコミットメッセージ（1種類のみ）** を提案します。

---

## 1. 実行手順

### ステップ 1: 対象要件ファイルとタスクの確認
1. ユーザーが指定した要件ファイル（`docs/requirements/REQ-XXX-<slug>.md`）および対象タスクを確認します。
2. 現在の Git 状態（`git branch --show-current`, `git status`, `git diff`, `git diff --staged`）を確認します。

### ステップ 2: ブランチ名の提案（作業開始時・未作成時）
- 現在 `main`（またはデフォルトブランチ）にいる場合や、ブランチ名の提案を求められた場合は、要件ファイルに記載されたブランチ名（未記載の場合は `<prefix>/<short-description>` 規則に従った名前）を **1種類のみ** 提案します。
- 複数案は提示せず、そのまま実行できるコマンド例（`git switch -c <branch-name>`）を添えて提示します。

### ステップ 3: コミットメッセージの提案（タスク実装時・コミット時）
1. 要件ファイル内の対象タスクの「提案コミットメッセージ」をベースにしつつ、**実際のコード変更差分（`git diff`）** を反映して精緻化します。
2. 提案は **必ず1種類のみ** とし、以下のフォーマットを厳守します（コミットメッセージだけで PR の説明文にも使える詳しさにする）：

```text
<type>(<scope>): <変更の要約（日本語・50文字目安・末尾に句点「。」をつけない）>

## 背景・目的
<なぜこの変更が必要なのか、解決する課題や対応する要件タスク（REQ-XXX タスクN）の背景>

## 変更内容
- <実際に変更・追加・削除したファイルやロジックの具体的内容 1>
- <実際に変更・追加・削除したファイルやロジックの具体的内容 2>

## 影響範囲・備考
- <影響を受けるモジュール・OS（macOS / Windows）・対象機器（Brother / 汎用eSCL）>
- <破壊的変更の有無、テスト結果、特記事項>
```

### ステップ 4: 要件ファイルのタスク状態更新
- タスクの実装・コミットが完了した際は、対応する `docs/requirements/REQ-XXX-<slug>.md` 内の該当タスクの状態を `[x] 完了` に更新します（すべてのタスクが完了した場合は要件ファイルのステータスも `完了` に更新します）。
