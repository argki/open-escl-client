# プルリクエスト文章提案スキル (`propose-pull-request`)

対象ブランチのコミットメッセージ群（構造化された背景・変更内容・影響範囲）と要件定義ファイルを集約し、日本の開発現場でベストプラクティスとされるテンプレート（[`.github/pull_request_template.md`](../../../.github/pull_request_template.md)）に準拠した **プルリクエストのタイトル（1種類）と本文（1種類）** を提案します。

---

## 1. 情報収集手順

1. **現在のブランチと差分の確認**:
   - `git branch --show-current` で現在のブランチ名を確認します。
   - ベースブランチ（通常は `main`）からのコミット履歴を `git log main..HEAD` で取得します（まだベースブランチがない初期状態やコミット前の場合は `git log` および `git status` / `git diff` を確認します）。
2. **対応する要件ファイルの確認**:
   - `docs/requirements/` 配下から、現在のブランチに対応する要件ファイル（`REQ-XXX-<slug>.md`）を読み込みます。

---

## 2. プルリクエスト文面の作成ルール

- **提案数**: タイトル・本文ともに、最も適切な **1種類のみ** を提案します（複数案を並べない）。
- **コミットメッセージからの集約**:
  - 本リポジトリのコミットメッセージには、すでに `## 背景・目的` / `## 変更内容` / `## 影響範囲・備考` が PR レベルの粒度で記載されています。
  - ブランチ内に1コミットしかない場合はそのコミットメッセージをベースに整形し、複数コミット（複数タスク）がある場合は各コミットの内容を論理的に統合・整理して PR 本文を構成します。

---

## 3. 出力フォーマット

以下の形式で、コピー＆ペースト（または `gh pr create`）ですぐに使える **PRタイトル** と **PR本文** を提示します。

### PR タイトル
```text
<type>(<scope>): <ブランチ全体の変更要約（日本語・50文字目安・句点なし）>
```

### PR 本文
```markdown
## 概要
- **対象要件ファイル**: `docs/requirements/REQ-XXX-<slug>.md`
- **関連Issue**: <!-- 該当がある場合のみ記載、なければ「なし」 -->

<このPRで達成する目的・解決する課題を1〜3文で簡潔に記載>

## 背景・目的
<各コミットの「背景・目的」および要件ファイルの背景を統合して記載>

## 変更内容
- <タスク1（コミット1）で実装した主要な変更点>
- <タスク2（コミット2）で実装した主要な変更点>

## 影響範囲
- **対象OS**: <macOS（最優先ターゲット） / Windows への影響有無>
- **対象機器**: <Brother eSCL対応機 / 汎用eSCLスキャナへの影響有無>
- **既存機能・破壊的変更**: <既存モジュールへの影響や破壊的変更の有無>

## 動作確認・テスト
- [ ] Brother × macOS 環境（またはモック環境）での動作確認
- [ ] 単体テスト・結合テストの追加およびパス確認
- [ ] Windows 環境および汎用 eSCL 機器との互換性を損なうハードコードがないことの確認
- [ ] ビルドエラー・Lint警告がないことの確認

## レビュアーへの特記事項・補足
- <重点的にレビューしてほしい設計判断や、別ブランチ（別要件ファイル）へ切り出したスコープ外事項など>
```
