# REQ-005: 複数原稿の自動検出・個別トリミング・余白微調整および高精度な角度補正・自動回転機能

- **ステータス**: `未着手`
- **優先ターゲット**: Brother × macOS（汎用 eSCL 機器・Windows 対応を考慮）
- **元要件（原案）**: [`docs/requirements/drafts/20261117.md`](./drafts/20261117.md)
- **依存する先行要件**: [`REQ-003`](./REQ-003-fast-preview-scan.md), [`REQ-004`](./REQ-004-scan-save-and-continuous-workflow.md)

## 1. 背景・目的

`docs/requirements/drafts/20261117.md` の「トリミング機能」および「プレビュー機能」における以下の要件を実現する。
- **複数の用紙を適当にスキャナーに置いてスキャンしても、正確にトリミングして複数ファイルとして保存できる**
- **微妙に余白ができてしまった場合などの微調整もできる**
- **正確な角度補正（微細な傾き補正およびスキャン内容に基づく 90°/180°/270° 自動回転）ができる**
  - 原稿がわずかに斜めに置かれた場合の微細な角度調整（Deskew）だけでなく、横向きや逆さまに置かれた原稿についても、スキャンした結果（文字の向きやレイアウト等）をもとに 90度・180度・270度自動的に回転して正しい向き（正立方向）に補正できること
- **自動トリミングおよび角度・向き補正が正しく行われているかをプレビュー画面で確認できる**

## 2. 要件概要とスコープ

### 実施すること（In Scope）
- スキャナガラス面（背景）の上に置かれた 1枚〜複数枚の用紙領域を OpenCV による輪郭抽出・最小外接矩形（`minAreaRect`）で自動検出するアルゴリズムの実装
- 各用紙の傾き角度を算出し、文字行や用紙エッジを基準に正確な微細角度補正（Deskew / 0.1度単位の回転補正・アフィン変換）を行って真っ直ぐな矩形に切り出す処理の実装
- 切り出した各スキャン画像の内容（文字の向き・行方向・天地特徴等）をもとに正しい向きを自動判定し、**0° / 90° / 180° / 270° の自動回転（自動向き・天地補正）**を行う機能の実装
  - macOS（最優先ターゲット）での高精度判定バックエンド（例: macOS Vision フレームワーク等のネイティブ機能活用）と、Windows を含む他環境・フォールバック用のクロスプラットフォーム判定バックエンドを抽象化インターフェースで分離する
- 切り出し領域に対して、周囲の余白（マージン）を一括または個別に「内側へ削る（負の余白：フチの影や微妙な余白を除去）／外側へ広げる（正の余白）」微調整パラメータ、手動枠ドラッグ調整、および 90° 単位の手動回転上書き（写真や図版など自動判定が曖昧な場合の補正）
- プレビューキャンバス上で自動検出された複数枚の切り出し枠・微細傾き補正・自動回転（0°/90°/180°/270°）の結果を視覚的に確認・微調整し、本スキャン時に連番の複数ファイルとして一括保存する機能

### 今回のブランチでは実施しないこと（Out of Scope / 別要件へ分割）
- 市販キャリブレーションターゲットを用いた光学・幾何学歪み補正（`REQ-006` で実施）

## 3. 完了条件（Acceptance Criteria）

- [ ] ガラス面に複数の用紙（写真、レシート、カード、書類など）を離して斜めに置いた画像から、各用紙の領域と微細な傾き角度が個別に自動検出・補正されること
- [ ] 横向き（90° / 270°）や上下逆さま（180°）に置いた原稿をスキャンした場合でも、スキャン結果の内容をもとに自動的に 90° / 180° / 270° 回転され、正しい向き（正立状態）で補正されること
- [ ] プレビュー画面上で、自動トリミングされた枠・微細な角度補正・自動回転（0°/90°/180°/270°）の結果が確認でき、必要に応じて 90° 単位の手動回転や角度微調整で上書きできること
- [ ] 微妙な余白が残った場合に、マージン微調整（mm または px 指定）やプレビュー上の枠調整によって綺麗に余白を除去できること
- [ ] 保存実行時に、検出・角度補正・自動回転された複数枚の原稿がネーミングルールに従った複数ファイル（連番）として個別に保存されること

### タスク 2: スキャン内容に基づく 90° / 180° / 270° 自動回転（自動向き・天地判定）機能の実装

- **状態**: `[ ] 未完了`
- **実装内容**:
  - スキャンして切り出した各原稿画像の内容（文字の向き・テキスト行方向・レイアウト・天地特徴等）を解析し、正立させるために必要な回転角度（`0`, `90`, `180`, `270` 度のいずれか）と信頼度スコアを推定・適用する `AutoOrientationCorrector` を実装する
  - OS 固有の認識エンジンと汎用アルゴリズムを分離する `OrientationDetectorBackend` インターフェースを定義し、以下のバックエンドを実装する:
    - **macOS 優先バックエンド**: macOS ネイティブの文字認識／向き解析機能（Vision フレームワーク等）を活用し、日本語・英語を含む文書の 0° / 90° / 180° / 270° を高精度に判定
    - **クロスプラットフォームフォールバックバックエンド**: Windows 環境やネイティブエンジン利用不可時でも動作する、OpenCV / 画像プロジェクション・文字形状特徴ベースの向き判定
  - 信頼度が閾値未満の画像（写真や文字を含まない図版等）は無理に回転せず `0°`（現状維持）とする安全設計を導入する
  - 0° / 90° / 180° / 270° に回転させたテスト文書画像を用いて、各向きの判定精度およびロスレス 90° 単位回転処理の正確さを検証する単体テストを追加する
- **提案コミットメッセージ**:

```text
feat(imaging): スキャン画像の内容から90/180/270度を自動判定して回転する向き補正機能を実装

## 背景・目的
原稿を横向き（90°/270°）や上下逆さま（180°）に置いてスキャンした場合でも、微細な傾き補正だけでなくスキャン結果の内容をもとに自動で正立方向へ回転できるようにするため（REQ-005 タスク2）。

## 変更内容
- `src/open_escl_client/imaging/orientation.py` を追加し、0°/90°/180°/270° の自動向き判定および回転適用を行う `AutoOrientationCorrector` と抽象バックエンド `OrientationDetectorBackend` を実装
- 最優先ターゲットである macOS 向けにネイティブ文字向き判定バックエンドを実装し、Windows 等でも動作するクロスプラットフォームのフォールバック判定バックエンドを分離実装
- 0°/90°/180°/270° 回転させた合成文書画像に対する自動回転精度・信頼度フォールバックの単体テストを追加

## 影響範囲・備考
- 対象OS: macOS（高精度ネイティブバックエンド優先）および Windows（クロスプラットフォームバックエンド）
- 文字の少ない写真・イラスト等では信頼度閾値により誤回転を防止し、UI 側の手動 90° 回転で調整可能とする
```

### タスク 5: 複数トリミング領域・角度補正・自動回転の一括個別ファイル保存パイプライン統合

- **状態**: `[ ] 未完了`
- **実装内容**:
  - 本スキャン実行時に、確定済みの複数トリミング枠（または本スキャン画像に対する再検出＋微調整オフセット）を用いて各原稿を個別に切り出し、微細傾き補正（Deskew）および 90° / 180° / 270° 自動回転（プレビューで手動変更された場合はその回転角を優先）を適用したうえで、`REQ-004` の `FileNamingEngine` / `ContinuousScanSession` と連携して連番付きの複数ファイル（またはマルチページ PDF）として一括保存する処理を統合する
- **提案コミットメッセージ**:

```text
feat(scan): 複数トリミング・角度補正・自動回転を適用して個別ファイル保存するパイプラインを統合

1回のスキャンでガラス面に様々な向きで並べた複数の用紙を、正確なトリミング・微細傾き補正・90°/180°/270°自動回転を適用したうえで、ネーミングルール（日付・連番等）に従った複数の個別ファイルとして自動的に分割保存できるようにするため（REQ-005 タスク5）。
```
