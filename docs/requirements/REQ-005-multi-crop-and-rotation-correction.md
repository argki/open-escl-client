# REQ-005: 複数原稿の自動検出・個別トリミング・余白微調整および高精度な角度補正・自動回転機能

- **ステータス**: `進行中`
- **優先ターゲット**: Brother × macOS（汎用 eSCL 機器・Windows 対応を考慮）
- **元要件（原案）**: [`docs/requirements/drafts/20261117.md`](./drafts/20261117.md)
- **依存する先行要件**: [`REQ-003`](./REQ-003-fast-preview-scan.md), [`REQ-004`](./REQ-004-scan-save-and-continuous-workflow.md)

## 1. 背景・目的

`docs/requirements/drafts/20261117.md` の「トリミング機能」および「プレビュー機能」における以下の要件を実現する。
- **複数の用紙を適当にスキャナーに置いてスキャンしても、正確にトリミングして複数ファイルとして保存できる**
- **微妙に余白ができてしまった場合などの微調整もできる**
- **正確な角度補正（微細な傾き補正およびスキャン内容に基づく 90°/180°/270° 自動回転）ができる**
  - 原稿がわずかに斜めに置かれた場合の微細な角度調整（Deskew）だけでなく、横向きや逆さまに置かれた原稿についても、スキャンした結果（文字の向きやレイアウト等）をもとに 90度・180度・270度自動的に回転して正しい向き（正立方向）に補正できること
- **自動トリミングおよび角度・向き補正が正しく行われているかをプレビュー画面で確認できる**

## 2. 要件概要とスコープ

### 実施すること（In Scope）
- スキャナガラス面（背景）の上に置かれた 1枚〜複数枚の用紙領域を OpenCV による輪郭抽出・最小外接矩形（`minAreaRect`）で自動検出するアルゴリズムの実装
- 各用紙の傾き角度を算出し、文字行や用紙エッジを基準に正確な微細角度補正（Deskew / 0.1度単位の回転補正・アフィン変換）を行って真っ直ぐな矩形に切り出す処理の実装
- 切り出した各スキャン画像の内容（文字の向き・行方向・天地特徴等）をもとに正しい向きを自動判定し、**0° / 90° / 180° / 270° の自動回転（自動向き・天地補正）**を行う機能の実装
  - macOS（最優先ターゲット）での高精度判定バックエンド（例: macOS Vision フレームワーク等のネイティブ機能活用）と、Windows を含む他環境・フォールバック用のクロスプラットフォーム判定バックエンドを抽象化インターフェースで分離する
- 切り出し領域に対して、周囲の余白（マージン）を一括または個別に「内側へ削る（負の余白：フチの影や微妙な余白を除去）／外側へ広げる（正の余白）」微調整パラメータ、手動枠ドラッグ調整、および 90° 単位の手動回転上書き（写真や図版など自動判定が曖昧な場合の補正）
- プレビューキャンバス上で自動検出された複数枚の切り出し枠・微細傾き補正・自動回転（0°/90°/180°/270°）の結果を視覚的に確認・微調整し、本スキャン時に連番の複数ファイルとして一括保存する機能

### 今回のブランチでは実施しないこと（Out of Scope / 別要件へ分割）
- 市販キャリブレーションターゲットを用いた光学・幾何学歪み補正（`REQ-006` で実施）

- [x] 微妙な余白が残った場合に、マージン微調整（mm または px 指定）やプレビュー上の枠調整によって綺麗に余白を除去できること

### タスク 2: スキャン内容に基づく 90° / 180° / 270° 自動回転（自動向き・天地判定）機能の実装

- **実装内容**:

### タスク 12: 辺の検出信頼度評価と一般的な定型用紙アスペクト比に基づく未検出辺の補完ロジック実装

- **状態**: `[ ] 未着手`
- **背景（実機確認・追加調査で判明した課題）**:
  - 前回と同じ置き方で 2 枚のハガキ（`100 × 148 mm`）をスキャンした場合でも、スキャナ光源の照射方向や白地部分の紙質により、**片側の長辺（`148 mm` 相当）には鮮明な紙端影線（例: 輝度低下 `> 40`、連続支持率ほぼ 100%）が現れる一方、対向する長辺や短辺側には影線がほとんど現れないケース** が発生する。
  - 下側の「ご留意事項」ハガキの実測値では、長辺側が `148.8 mm`（`361.1 px`）とほぼ実寸通りに検出できているにもかかわらず、影線の弱い短辺側が `94.2 mm`（`228.5 px`）で止まっており、**実際のハガキ（`100 × 148 mm`）より小さく切り出され、端の文字（左端番号や上側余白）が枠線ギリギリになる** 事象を確認した。
  - 上側のハガキ等でも、印刷枠サイズより実紙外周が一回り大きいケースや、1〜2 辺のみ強く検出できて残りの辺の検出率が悪いケースでは、未検出辺側だけ内縮してしまう。
- **実装内容**:
  - `MultiDocumentDetector` における辺検出結果（`off_t`, `off_r`, `off_b`, `off_l` および外周影連続支持率・明るさステップ強度・縁取りカード判定）から、**4 辺それぞれに検出信頼度スコア（高信頼度アンカー辺 vs 未検出・低信頼度辺）** を付与する仕組みを実装する。
  - 高信頼度で確定している辺（特に 2 本の平行対向辺または長辺/短辺の代表辺）を基準（アンカー）として固定し、**未検出・低信頼度辺が実寸より小さく止まっていると判定される場合** に、一般的な定型用紙比率（ハガキ `100:148 (1.480)`、L 判 `89:127 (1.427)`、KG 判 `102:152 (1.490)`、A/B 判 `1:1.414`、2L 判 `127:178 (1.402)`、名刺 `55:91 (1.655)` 等）および必要に応じた DPI ベースの物理寸法整合性を参照して、不足分を外側（白地方向）へ補完拡張するロジックを実装する。
  - **非回帰・安全ガードの徹底**:
    - 細長い感熱紙レシートや保証書添付スリップ等の非定型比率原稿（例: アスペクト比 `> 1.90` や `< 1.15`）、およびすでに 4 辺すべてが高信頼度で確定している縁取りハガキ・写真等へ誤って比率引き伸ばしを行わない。
    - 拡張先が隣接原稿（`solid_boxes` や他の検出グループ）や非白地（別の印刷物・暗い背景領域）・画像端と衝突する場合はその手前で安全に停止する。
    - `DetectionConfig` から定型比率補完機能の有効/無効や参照プリセット挙動を制御可能にし、既存のレシート 3 枚＋保証書スリップ・A4 全面・A3 内 A4・縁取りハガキのテストに影響しないことを維持する。
  - 「片側の長辺影線のみで対向辺・短辺の影線がない白地ハガキ（`100 × 148 mm` 相当）が、高信頼度の長辺を基準に `1:1.48` 比率で短辺の白余白・端文字を含めた実ハガキ外周サイズまで正確に補完されるテスト」および「長尺レシートや 4 辺確定済み縁取りハガキが比率補完によって歪まない非回帰テスト」を追加する。
