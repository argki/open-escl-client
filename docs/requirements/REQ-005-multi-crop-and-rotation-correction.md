# REQ-005: 複数原稿の自動検出・個別トリミング・余白微調整および高精度な角度補正機能

- **ステータス**: `未着手`
- **優先ターゲット**: Brother × macOS（汎用 eSCL 機器・Windows 対応を考慮）
- **元要件（原案）**: [`docs/requirements/drafts/20261117.md`](./drafts/20261117.md)
- **依存する先行要件**: [`REQ-003`](./REQ-003-fast-preview-scan.md), [`REQ-004`](./REQ-004-scan-save-and-continuous-workflow.md)

## 1. 背景・目的

`docs/requirements/drafts/20261117.md` の「トリミング機能」および「プレビュー機能」における以下の要件を実現する。
- **複数の用紙を適当にスキャナーに置いてスキャンしても、正確にトリミングして複数ファイルとして保存できる**
- **微妙に余白ができてしまった場合などの微調整もできる**
- **正確な角度補正（傾き補正）もできる**
- **自動トリミング時に正しくトリミングされているかをプレビュー画面で確認できる**

## 2. 要件概要とスコープ

### 実施すること（In Scope）
- スキャナガラス面（背景）の上に置かれた 1枚〜複数枚の用紙領域を OpenCV による輪郭抽出・最小外接矩形（`minAreaRect`）で自動検出するアルゴリズムの実装
- 各用紙の傾き角度を算出し、文字行や用紙エッジを基準に正確な角度補正（回転補正 / アフィン変換）を行って真っ直ぐな矩形に切り出す処理の実装
- 切り出し領域に対して、周囲の余白（マージン）を一括または個別に「内側へ削る（負の余白：フチの影や微妙な余白を除去）／外側へ広げる（正の余白）」微調整パラメータおよび手動枠ドラッグ調整
- プレビューキャンバス上で自動検出された複数枚の切り出し枠・傾き補正結果を視覚的に確認・微調整し、本スキャン時に連番の複数ファイルとして一括保存する機能

### 今回のブランチでは実施しないこと（Out of Scope / 別要件へ分割）
- 市販キャリブレーションターゲットを用いた光学・幾何学歪み補正（`REQ-006` で実施）

## 3. 完了条件（Acceptance Criteria）

- [ ] ガラス面に複数の用紙（写真、レシート、カード、書類など）を離して斜めに置いた画像から、各用紙の領域と傾き角度が個別に自動検出されること
- [ ] プレビュー画面上で、自動トリミングされた枠と角度補正後のイメージが確認できること
- [ ] 微妙な余白が残った場合に、マージン微調整（mm または px 指定）やプレビュー上の枠調整によって綺麗に余白を除去できること
- [ ] 保存実行時に、検出された複数枚の原稿がネーミングルールに従った複数ファイル（連番）として個別に保存されること

## 5. タスク一覧（1タスク ＝ 1コミット）

### タスク 1: 複数用紙の自動領域検出と高精度な角度補正（Deskew）エンジンの実装

- **状態**: `[ ] 未完了`
- **実装内容**:
  - スキャン画像からスキャナ原稿台の背景（白または黒マット）と原稿領域を分離し、複数の用紙それぞれの回転外接矩形（中心座標・幅・高さ・回転角度）を検出する `MultiDocumentDetector` を実装する
  - 用紙の外周エッジ直線（ハフ変換 / `minAreaRect`）および内部の文字列・罫線方向から 0.1度単位で正確な傾き角を算出し、サブピクセル補間で回転・切り出しを行う `DeskewCropProcessor` を実装する
- **提案コミットメッセージ**:

```text
feat(imaging): 複数原稿の自動領域検出と高精度な角度補正(Deskew)エンジンを実装

## 背景・目的
複数の用紙をスキャナに無造作（斜め・複数枚同時）に置いてスキャンした場合でも、各用紙の位置と傾きを正確に自動検出し、真っ直ぐに補正された個別画像として切り出せるようにするため（REQ-005 タスク1）。

## 変更内容
- `src/open_escl_client/imaging/multi_crop.py` を追加し、画像内の複数原稿領域（回転矩形 `RotatedCropBox`）を自動検出する `MultiDocumentDetector` を実装
- 用紙エッジと内部構造から正確な傾き角度を算出し、回転補正と切り出しを行う `DeskewCropProcessor` を実装
- 複数枚の傾いた合成テスト画像を用いて、検出数・角度誤差・切り出し精度を検証する単体テストを追加

## 影響範囲・備考
- 低解像度プレビュー画像での高速枠検出と、高解像度本スキャン画像での本切り出しの双方で利用可能
```

### タスク 2: トリミング余白の微調整（マージン増減・個別頂点/辺オフセット）ロジックの実装

- **状態**: `[ ] 未完了`
- **実装内容**:
  - 自動検出された各トリミング枠に対して、上下左右一括または個別の余白オフセット（例: `-1.5mm` で周囲の微妙な余白や影をカット、`+2.0mm` で余裕を持たせる）および手動での枠位置・角度調整を適用するモデルと座標変換処理を実装する
  - 低解像度プレビュー上で微調整した枠パラメータ（正規化座標・ミリメートル単位）を、高解像度の本スキャン画像へ正確にスケール変換して適用する仕組みを実装する
- **提案コミットメッセージ**:

```text
feat(imaging): トリミング枠の余白微調整(マージン加減算・手動補正)とDPIスケール変換を実装

## 背景・目的
自動トリミング時に用紙の端に微妙な余白や影が残ってしまった場合でも、ユーザーが余白量や枠の位置・角度を細かく微調整し、その結果を本スキャン時の高解像度画像にも正確に反映できるようにするため（REQ-005 タスク2）。

## 変更内容
- `RotatedCropBox` に上下左右の余白オフセット（mm / px 指定）および手動調整値を保持・適用するメソッドを追加
- プレビュー解像度上で確定・微調整した複数のトリミング枠を、本スキャン解像度のピクセル座標へ正確に変換するマッピング処理を実装
- 余白の削り込み（負のオフセット）および拡張（正のオフセット）の境界値テストを追加

## 影響範囲・備考
- プレビューで確認・微調整した通りの切り出し範囲が本スキャン保存時にも再現される
```

### タスク 4: 複数トリミング領域の一括個別ファイル保存パイプライン統合

- **状態**: `[ ] 未完了`
- **実装内容**:
  - 本スキャン実行時に、確定済みの複数トリミング枠（または本スキャン画像に対する再検出＋微調整オフセット）を用いて各原稿を個別に切り出し、`REQ-004` の `FileNamingEngine` と連携して連番付きの複数ファイル（またはマルチページ PDF）として一括保存する処理を統合する
- **提案コミットメッセージ**:

```text
feat(scan): 複数トリミングされた各原稿を個別ファイルとして一括保存するパイプラインを統合

## 背景・目的
1回のスキャンでガラス面に並べた複数の用紙を、ネーミングルール（日付・連番等）に従った複数の個別ファイルとして自動的に分割保存できるようにするため（REQ-005 タスク4）。

## 変更内容
- 本スキャン完了後に `DeskewCropProcessor` で複数領域を個別画像として切り出し、`FileNamingEngine` で連番を振りながら順次 `ImageExporter` で書き出す保存パイプラインを実装
- 1回のスキャンから3枚の原稿が検出された場合に3つの連番ファイルが出力される結合テストを追加

## 影響範囲・備考
- 連続スキャンモード（REQ-004）とも連携し、複数回に分けてスキャンした場合でも連番が途切れず保存される
```
