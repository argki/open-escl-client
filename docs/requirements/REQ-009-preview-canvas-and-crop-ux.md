# REQ-009: プレビューキャンバスの操作性向上・切り出し拡大表示と検出枠ドラッグ修正

- **ステータス**: `未着手`
- **優先ターゲット**: Brother × macOS（クロスプラットフォーム・汎用eSCL拡張を考慮）
- **元要件（原案）**: [`docs/requirements/drafts/20261120.md`](./drafts/20261120.md)
- **依存する先行要件**: [`REQ-003`](./REQ-003-fast-preview-scan.md), [`REQ-005`](./REQ-005-multi-crop-and-rotation-correction.md)

---

## 1. 背景・目的

現在のプレビュー画面およびトリミング枠操作には、日常利用における以下の UX 課題が存在する。
1. 初期ウィンドウサイズ（`1180 × 780`）では、プレビューヘッダー右上の拡大縮小ボタンや下部サムネイルストリップ右上の案内テキストが右端からはみ出して見切れる。
2. プレビューの拡大縮小が右上ボタンのクリックのみで、マウスホイールによる直感的なズームやスクロールバー表示に対応していない。
3. 高速プレビュー時に、下のカードにある切り出し結果を上の大きいキャンバスで確認したいケースがある（全体像に戻すボタン／サムネイルも欲しい）。
4. 検出枠の移動・四隅リサイズをドラッグすると引っかかってスムーズに調整できない（原因：`CropOverlay.qml` が `Repeater` のモデル配列 `cropBoxes` 変更のたびに全 delegate を再生成して `MouseArea` のドラッグ状態がリセットされること、および 1 フレームごとに同期サムネイル再生成が走っていること）。また、設定中の規格比率を維持したまま枠サイズを調整できるかも保証したい。

## 2. 要件概要とスコープ

### 実施すること（In Scope）
- 初期ウィンドウサイズ（および最小サイズ `920 × 620`）でも `PreviewArea.qml` のヘッダー・ズームボタン・下部案内テキストが右側へはみ出さないよう `elide` / `wrapMode` / `Layout.minimumWidth: 0` 等のレスポンシブ配置を修正する
- `PreviewArea.qml` のプレビュー領域でマウスホイール（またはトラックパッドピンチ／スクロール＋修飾キー等、通常のマウスホイール上下）によるズームイン・ズームアウト、および拡大時の水平・垂直スクロールバー表示を実装する
- 下部サムネイルストリップの左端に「全体像（原稿台）」サムネイルを固定配置し、各切り出しカードをクリックした際は上の大きいキャンバスへその切り出し結果（回転・裏写り反映済み）を大きく表示でき、「全体像」クリックで元の原稿台全体プレビュー＆枠編集モードへ戻せるようにする
- `CropOverlay.qml` および `AppViewModel` における検出枠ドラッグ操作の途切れ・カクつきを根本解消し（ドラッグ中はローカル座標プレビューまたはモデル全再生成を避け、ドロップ時にサムネイルを再生成）、指定中の用紙規格比率（`aspectRatioPreset` 等）を維持した四隅リサイズにも対応する

### 今回のブランチでは実施しないこと（Out of Scope / 別要件へ分割）
- 設定永続化（`REQ-008` で実施）
- 左サイドバーの折りたたみ整理（`REQ-010` で実施）

## 3. 完了条件（Acceptance Criteria）

- [ ] 初期ウィンドウサイズ（`1180 × 780`）および最小幅（`920 px`）で、右上の拡大縮小ボタンや下部テキストがウィンドウ右側へはみ出ないこと
- [ ] マウスホイールでプレビューキャンバスの拡大縮小ができ、拡大時にドラッグ移動とスクロールバー表示の両方が機能すること
- [ ] 下部サムネイルクリックで上部のメイン表示が該当切り出し結果に切り替わり、左端の「全体像」サムネイルクリックで元の全体プレビューへ戻ること
- [ ] 検出枠の移動・四隅リサイズを途切れなく滑らかにドラッグでき、必要に応じて選択中の規格比率を維持したリサイズができること
- [ ] Brother × macOS 環境（またはモック検証）で意図通り動作すること

### タスク 3: 検出枠ドラッグ調整（移動・リサイズ）の途切れ根本修正と比率維持リサイズ対応

- **状態**: `[ ] 未完了`
- **実装内容**:
  - **途切れ原因の修正**: `src/open_escl_client/ui/qml/CropOverlay.qml` において、`Repeater` への全配列再代入による delegate 破棄で `MouseArea` ドラッグが中断する構造を見直し、ドラッグ中は QML ローカル状態（またはインデックス維持＋個別データバインディング更新／Canvas 再描画のみ）で滑らかに枠を動かし、ドラッグ中毎フレームの重いサムネイル再生成は行わずリリース時（`onReleased`）に確定反映・サムネイル更新する方式へ改善する
  - **比率維持リサイズ対応**: `src/open_escl_client/imaging/multi_crop.py`（`drag_corner_to` / 新パラメータ `lock_aspect_ratio: bool`）および `AppViewModel.dragCropCornerToNorm` に、選択中の規格比率（`selectedCropAspectRatioPreset` が `auto`/`free` 以外で比率が定まっている場合、または「比率を維持して枠調整」トグル／Shift キー押下時）を維持したまま対角頂点固定で四隅を拡大縮小できるロジックを追加する
  - `tests/imaging/test_crop_adjustments.py` と `tests/ui/test_qml_load.py` にドラッグ完了後の一貫性および比率ロック付きコーナーリサイズのテストを追加する
- **提案コミットメッセージ**:

```text
fix(ui,imaging): トリミング枠ドラッグ時の途切れ・カクつき解消と比率維持リサイズを実装

## 変更内容
- `src/open_escl_client/ui/qml/CropOverlay.qml` および `src/open_escl_client/ui/viewmodel.py` を見直し、ドラッグ中のモデル破棄と重いサムネイル再生成を分離して滑らかな連続ドラッグとリリース時確定更新を実装
- `src/open_escl_client/imaging/multi_crop.py` と `AppViewModel.dragCropCornerToNorm` に指定規格比率（または現在比率）を維持して四隅リサイズを行う比率ロック計算を追加
- `tests/imaging/test_crop_adjustments.py` と `tests/ui/test_qml_load.py` に連続ドラッグ・比率維持リサイズの検証テストを追加

```
