# 要件定義ディレクトリ (`docs/requirements/`)

本ディレクトリは、`open-escl-client` の開発要件およびタスク分解後のブランチ単位要件ファイルを管理する場所です。

---

## 1. ディレクトリ構成と役割

```text
docs/requirements/
├── README.md                  # 本ガイド
├── drafts/                    # ユーザーが記述する未分解の要件・アイデア・原案の置き場
│   └── .gitkeep
└── REQ-XXX-<slug>.md          # ブランチ単位（1ブランチ＝1ファイル）に分解・整形された要件ファイル
```

- **原案の作成場所**:
  - 新しい要件やアイデアを書く際は、`docs/requirements/drafts/` 配下（または `docs/requirements/` 直下でも可）に自由な形式の Markdown ファイルとして作成してください。
- **分解後の要件ファイル (`REQ-XXX-<slug>.md`)**:
  - タスク分解スキル（`decompose-requirements`）を実行すると、原案の規模や関心事のまとまりを分析し、**「1つの Git ブランチ（＝1つのプルリクエスト）で実施すべき適切な粒度」** ごとに `docs/requirements/REQ-XXX-<slug>.md` として作成・分割されます。
  - 各要件ファイルの中には、**「1タスク ＝ 1コミット」** の粒度で分解されたタスク一覧、**提案する Git ブランチ名（1種類）**、および **各タスクに対応する構造化コミットメッセージ案（1種類）** が記載されます。

---

## 2. 開発の流れ（ワークフロー）

1. **要件の記述**:
   - `docs/requirements/drafts/`（または `docs/requirements/` 直下）に、実現したい機能や要件を記述します。
2. **要件のタスク分解 (`decompose-requirements` スキル)**:
   - Antigravity に「この要件をタスク分解して」と依頼します。
   - 1つのブランチで実施すべきでない（規模が大きい・複数の機能が含まれる）と判断された場合は、適切な数のブランチ単位要件ファイル（`REQ-001-...`, `REQ-002-...`）に分解されます。
   - 各ファイルには、切るべきブランチ名（1種類）と、コミット単位のタスクおよび各コミットメッセージ案（1種類）が出力されます。
3. **タスクの実施とコミット (`propose-git-commit` スキル)**:
   - 分解された要件ファイル（`REQ-XXX-<slug>.md`）のブランチを作成し、記載されたタスクを1つずつ（1タスク＝1コミットで）実施します。
   - 実装結果に応じて、実際の変更差分を反映した PR レベルのコミットメッセージ（1種類）を提案・適用します。
4. **プルリクエストの作成 (`propose-pull-request` スキル)**:
   - ブランチ内の全タスクが完了したら、Antigravity に「プルリクエストの文章を提案して」と依頼します。
   - 要件ファイルと各コミットメッセージ（Why / What / Impact）を集約し、[`.github/pull_request_template.md`](../../.github/pull_request_template.md) に準拠した PR タイトルと本文（1種類）を生成します。
