# REQ-004: 保存設定（フォルダ・命名規則・形式・圧縮率・DPI）と同一設定での連続スキャン機能

- **ステータス**: `未着手`
- **優先ターゲット**: Brother × macOS（Windows 対応を考慮）
- **元要件（原案）**: [`docs/requirements/drafts/20261117.md`](./drafts/20261117.md)
- **依存する先行要件**: [`REQ-003`](./REQ-003-fast-preview-scan.md)

---

## 1. 背景・目的

`docs/requirements/drafts/20261117.md` の「保存機能」における以下の要件を実現する。
- デフォルトで保存するフォルダが指定できる
- 任意のネーミングルールで保存ができる（連番の付け方や日付を入れるなど）
- 一度プレビューして問題なければ、同じ設定で連続してスキャンできる
- ファイル形式は PDF や JPG など一般的な画像形式が選べ、圧縮率や解像度（DPI）なども選べる

## 2. 要件概要とスコープ

### 実施すること（In Scope）
- デフォルト保存先フォルダやスキャン設定を OS 標準のユーザー設定領域へ保存・復元する設定管理機能
- 日付（`{date}`, `{yyyy}{mm}{dd}`）、時刻（`{time}`）、連番（`{seq:03d}` 等、桁数指定可）、任意のプレフィックスを組み合わせられるネーミングルールエンジンと既存ファイルの上書き防止制御
- 保存フォーマット（JPEG / PNG / PDF）、本スキャン解像度（DPI）、および圧縮率（JPEG 品質 1〜100、PDF 内の画像圧縮品質）の指定とファイル書き出し機能
- 一度プレビューして仕上がりを確認した後、プレビューをやり直さずに同じ設定・同じネーミングルール（連番自動カウントアップ）で次々と原稿を入れ替えて本スキャンできる「連続スキャン」機能

### 今回のブランチでは実施しないこと（Out of Scope / 別要件へ分割）
- 複数用紙の自動分割トリミング（`REQ-005` で実施）
- カラーキャリブレーションや裏写り補正フィルタの適用（`REQ-006`, `REQ-007` で実施）

## 3. 完了条件（Acceptance Criteria）

- [ ] デフォルト保存先フォルダを指定でき、アプリ再起動後も保持されること
- [ ] `Scan_{date}_{seq:03d}` のようなネーミングルールで日付や連番付きのファイル名が自動生成され、プレビュー確認画面でも次の保存ファイル名が事前に確認できること
- [ ] JPEG / PNG / PDF の各形式で、指定した解像度（DPI）と圧縮率（品質）が反映されて保存されること
- [ ] プレビュー確認後、「スキャンして保存（連続スキャン対応）」ボタンを押すたびに同じ設定で即座に本スキャンが走り、連番が自動でインクリメントされて保存されること

## 5. タスク一覧（1タスク ＝ 1コミット）

### タスク 1: デフォルト保存フォルダ管理と柔軟なファイルネーミングルールエンジンの実装

- **状態**: `[ ] 未完了`
- **実装内容**:
  - デフォルト保存フォルダや命名テンプレートを永続化する `UserConfigStore`（macOS / Windows 両対応パス処理）を実装する
  - `{date}`（例: `20261117` またはフォーマット指定）、`{time}`、`{seq:03d}`（任意の桁数の連番）、任意の文字列を組み合わせたテンプレートを展開し、保存先フォルダ内の既存ファイルと重複しない次の連番を自動解決する `FileNamingEngine` を実装する
- **提案コミットメッセージ**:

```text
feat(config): デフォルト保存先設定と日付・連番対応ネーミングルールエンジンを実装

## 背景・目的
毎回の保存時にフォルダやファイル名を手入力する手間を省き、日付や連番の付け方をユーザーの好みに合わせて柔軟にカスタマイズできるようにするため（REQ-004 タスク1）。

## 変更内容
- `src/open_escl_client/config/user_config.py` を追加し、デフォルト保存フォルダやスキャン設定をOS標準のユーザー設定ディレクトリへ永続化する機能を実装
- `src/open_escl_client/core/naming.py` を追加し、`{date}`, `{time}`, `{seq:03d}` 等のトークン展開と既存ファイルとの重複回避を行う `FileNamingEngine` を実装
- ネーミングルール展開および連番インクリメントの単体テストを追加

## 影響範囲・備考
- 対象OS: macOS / Windows 共通（`pathlib.Path` によりOS間のパス区切り文字差異を吸収）
```

- **実装内容**:

  - JPEG 保存時の品質（圧縮率 `quality: 1-100`）および DPI メタデータ埋め込み、PNG 保存時の圧縮レベル、PDF 保存時の DPI に基づく物理ページサイズ（mm）設定と画像圧縮率制御（`img2pdf` / `Pillow` 連携）を実装する
- **提案コミットメッセージ**:

```text
feat(scan): ファイル形式(PDF/JPEG/PNG)・圧縮率・DPI指定に対応した保存エクスポータを実装

## 背景・目的
用途（高画質アーカイブや軽量な書類共有など）に応じて、PDFやJPEGなどの一般的な画像形式、読み取り解像度（DPI）、圧縮率を自由に選択して保存できるようにするため（REQ-004 タスク2）。

## 変更内容
- `src/open_escl_client/core/exporter.py` を追加し、JPEG・PNG・PDFの各フォーマットでのファイル出力処理を実装
- 選択されたDPI（解像度）のメタデータ付与と、圧縮率（品質パラメータ）に応じたデータサイズ制御を実装
- 各フォーマットの出力結果・DPIメタデータ・ファイルサイズ変化を検証する単体テストを追加

## 影響範囲・備考
- PDF出力時は読み取りDPIに応じた正確な実寸サイズ（A4/B5等）でページが生成される
```

### タスク 3: プレビュー設定を引き継いで繰り返し本スキャンできる連続スキャン制御の実装

- **状態**: `[ ] 未完了`
- **実装内容**:
  - プレビューで確認・確定したスキャン条件（対象領域・色設定・保存フォーマット・圧縮率・本スキャン用 DPI）を保持したまま、ワンアクションで本スキャン＋連番ファイル保存を連続実行できる `ContinuousScanSession` を実装する
  - 複数ページを1つの PDF にまとめるモードと、1スキャンごとに連番の別ファイルとして保存するモードの両方に対応する
- **提案コミットメッセージ**:

```text
feat(scan): プレビュー確認後に同一設定で繰り返しスキャン・保存できる連続スキャン機能を実装

## 背景・目的
一度プレビューして色合いや範囲に問題がないことを確認した後は、毎回プレビューを挟むことなく、同じ設定のまま原稿を入れ替えて次々と高速にスキャン・保存できるようにするため（REQ-004 タスク3）。

## 変更内容
- `src/open_escl_client/core/continuous_scan.py` を追加し、確定したスキャン条件とネーミングルールの連番状態を保持して連続実行する `ContinuousScanSession` を実装
- 1スキャンごとに連番ファイルとして即座に保存するフローと、連続スキャンした複数枚を1つのPDFとして保存するフローを実装
- 連続スキャン時の連番カウントアップと設定維持に関する単体テストを追加

## 影響範囲・備考
- 後続のトリミング設定（REQ-005）や色補正設定（REQ-006/007）もこの連続スキャンセッションに自動で引き継がれる設計とした
```
